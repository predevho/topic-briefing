# 공개 전 점검

이 리포지토리는 **비공개**다. 공개로 바꾸기 전에 아래를 확인한다.

마지막 점검: 2026-11-12 (커밋 `0f2fa61`, 추적 파일 63개)

## 1. 조치가 필요한 것

### 커밋 작성자 이메일이 36개 커밋 전부에 있다

```
$ git log --format="%ae" | sort -u
dlagusgh7894@gmail.com
```

파일 내용에는 없고 **커밋 메타데이터**에만 있다. 공개하면 모든 커밋에서
보이고 스팸 수집 대상이 된다.

**지금 설정을 바꿔도 기존 커밋은 그대로 남는다.** 히스토리를 다시 써야 한다.

앞으로의 커밋만 바꾸려면:

```bash
git config user.email "predevho@users.noreply.github.com"
```

기존 36개 커밋까지 바꾸려면 히스토리 재작성이 필요하다. **공개 직전에
한 번 하는 것이 가장 싸다** — 지금은 원격에 혼자이고 협업자가 없어서
강제 푸시의 대가가 없다. 나중에 PR이나 포크가 생기면 비싸진다.

```bash
# git-filter-repo 설치 후 (brew install git-filter-repo)
git filter-repo --email-callback '
  return b"predevho@users.noreply.github.com" if email == b"dlagusgh7894@gmail.com" else email
'
git push --force origin main
```

GitHub 설정에서 *Settings → Emails → Keep my email addresses private*도 켠다.

## 2. 본인이 판단할 것 (위험하지는 않다)

### `config/interests.md` — 개인 프로필 49줄

직업("백엔드 개발자"), 관심 분야, **이미 충분히 아는 주제**, 지루하게
느끼는 주제가 적혀 있다. 민감 정보는 아니지만 읽는 취향이 드러난다.

공개하고 싶지 않으면 두 가지 방법이 있다.

- `config/interests.md`를 `.gitignore`에 넣고 `config/interests.example.md`를
  일반적인 내용으로 커밋한다. 단, 이 파일은 선별 품질의 핵심이라 예시가
  빈약하면 리포지토리를 받은 사람이 재현할 수 없다.
- 그대로 둔다. 기술 관심사 서술이라 공개 이력서 수준이다.

### 실명 매체·기업에 대한 판단

`config/sources.yaml` 주석과 계획 문서에 측정 근거가 붙은 판단이 있다.

**전부 실측에 근거한 사실이고 날짜와 수치가 함께 있다.** 다만 공개되면
비판으로 읽힐 수 있다. 그대로 두려면 문구가 사실 서술인지 한 번 더 읽어
본다. 특히 "느린 발행이 아니라 중단으로 본다"처럼 **평가**가 섞인 문장을
확인한다.

## 4. 공개되지 않는 것 (확인했다)

- **`.env`** — `.gitignore`에 있고 히스토리에 한 번도 없었다
- **`data/`** — 한 번도 커밋되지 않았다. **시드 1,923건의 기사 본문**(타인의
  저작물)이 로컬과 `~/briefing-seed-backup/`에만 있다
- **Supabase 프로젝트 ref·URL** — 추적 파일에 한 건도 없다
- **실제 API 키** — Anthropic·Supabase 모두 없다. 레거시 JWT(`eyJ...`)도 없다
- **절대 경로** (`/Users/...`), **스크래치패드 경로**, **사용자명 문자열**,
  **IP 주소** — 전부 없다

## 점검 방법

내용 검사는 이렇게 다시 돌린다.

```bash
git ls-files -z | xargs -0 grep -nE \
  '/Users/|/private/tmp/claude-|[a-z0-9]{15,}\.supabase\.co|sb_secret_[A-Za-z0-9]|sk-ant-[A-Za-z0-9]|eyJ[A-Za-z0-9_-]{20,}'
```

**아무것도 나오지 않아야 한다.** `sb_secret_sentinel_...`만 나오면 정상이다
(가짜 키).

커밋 메타데이터는 따로 본다.

```bash
git log --all --format="%ae %an" | sort -u
```
